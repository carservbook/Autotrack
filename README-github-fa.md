## نسخهٔ 2.11.20 — «تناوب مسیر بخش‌ها» (فقط شِل؛ ورکر دست‌نخورده)

**این نسخه چه چیزی را حل می‌کند؟** اندازه‌گیری خود شما (curl روی مخابرات/همراه اول) نشان داد آپلودِ
بزرگ‌تر از ~۲۰-۳۰ کیلوبایت روی یک اتصال با RST قطع می‌شود. مرورگر برای هر دامنه از یک اتصال مشترک
استفاده می‌کند؛ پس حتی تکه‌های ۱۲KB پشت‌سرهم روی «یک اتصال» بعد از ~۲۰-۳۰KB تجمعی قطع می‌شدند.
2.11.20 بخش‌های زوج و فرد را روی دو اورجینِ «یک ورکر» می‌فرستد (بودجه بین دو اتصال/مسیر تقسیم می‌شود)،
در شکستِ هر بخش فقط همان بخش با مسیرِ دیگر دوباره می‌رود (نه کل پوش از صفر)، تعداد بخش‌ها همیشه
داخل سقف ورکر می‌ماند، «بخش ناقص 409» خودش را ترمیم می‌کند، بیکون پایانِ اپ روی شِل گیتهاب به
آدرس مطلق می‌رود، شاخهٔ بازیابیِ همگام‌سازی دستی هم از موتور مقاوم استفاده می‌کند، و «آخرین خطای
همگام‌سازی» حالا شمارهٔ بخش/حجم/مسیر را دقیق می‌گوید.

### انتشار (فقط صفحهٔ گیتهاب — ورکر فعلی دست‌نخورده می‌ماند)
1) هر ۱۱ فایل همین زیپ را در گیتهاب آپلود کنید (Add file → Upload files → همهٔ فایل‌ها).
2) اپ را دو بار کامل ببندید و باز کنید تا `نسخه: 2.11.20` در پروفایل دیده شود.
3) بعد از باز شدن، همگام‌سازی دستی بزنید؛ چیپ «ارسال بخش x از y» پیشرفت را نشان می‌دهد.
4) اگر خطا داد، «آخرین خطای همگام‌سازی» در پروفایل الان دقیق است (بخش/حجم/مسیر).

### نصب آفلاین (پاسخ به «اپ بدون اینترنت بالا نیاید»)
- اولین باز شدن بعد از نصب یک بار اینترنت می‌خواهد (طبیعت اپ وب)؛ بعد از همان بار، سرویس‌ورکر
  همهٔ فایل‌های اپ را کش می‌کند و هر باز شدن بعدی — حتی با اینترنت مرده — همان لحظه از کش باز
  می‌شود و همه‌چیز آفلاین کار می‌کند (ثبت/ویرایش/یادآور/گزارش) و با اولین اتصال خودکار همگام می‌شود.
- راه «آفلاین از همان نصبِ اول» فقط با پکیج اندرویدِ حاوی فایل‌های اپ ممکن است (نقشهٔ راه نسخهٔ بعدی بازار).

## تغییر v2.11.16 (پوش مقاوم — رفع «اتصال هست ولی همگام‌سازی نمی‌شود»)

- **پنجرهٔ پوش ۶۰ ثانیه (به‌جای ۲۰):** تستِ اتصال با پینگِ ~۱۰۰ بایتی است و روی شبکهٔ شلوغ
  رد می‌شود، ولی پوشِ واقعی (~۱۵۷ کیلوبایت) روی همان مسیر به ۲۰ ثانیه نمی‌رسید → تایم‌اوت.
  حالا پوش ۶۰ ثانیه برای هر مسیر فرصت دارد.
- **حافظهٔ «پوش-اثبات‌شده»:** پایه‌ای که آخرین پوشِ واقعی را کامل کرده، دفعهٔ بعد اول امتحان
  می‌شود — چون پاسخِ سبکِ تستِ اتصال لزوماً به معنی ردِشدنِ پوشِ سنگین نیست.
- **چرخش مسیر بعد از شکست:** اگر پوش روی هر دو مسیر تایم‌اوت شد، تلاشِ بعدی از مسیرِ دیگر
  شروع می‌شود (قبلاً روی همان مسیرِ چسبنده گیر می‌کرد).
- **تلاش مجدد سریع‌تر:** حداکثر فاصلهٔ تلاش خودکار ۵ دقیقه (قبلاً ۸ دقیقه).

## تغییر v2.11.15 (تشخیص شفاف + فیکس پیش‌پرواز)

- **تست اتصال داخل اپ:** پروفایل → «تست اتصال سرور (هر دو مسیر)» — هر دو مسیر
  (اصلی/پشتیبان) با سقف ۷ ثانیه پینگ می‌شوند و زمان پاسخ هرکدام نشان داده می‌شود.
  دیگر نیازی به تست دستی آدرس‌ها در مرورگر نیست.
- **آخرین خطای همگام‌سازی با علت دقیق:** تا حالا چیپ قرمز فقط می‌گفت «ناموفق بود»؛
  حالا علت (تایم‌اوت شبکه / قطع اتصال / پاسخ سرور با کد HTTP / حجم داده / نشست منقضی)
  و ساعتش ثبت و در پروفایل نشان داده می‌شود؛ علت کوتاه هم داخل خود چیپ قرمز می‌آید.
- **نشست منقضی (401):** اگر توکن حساب باطل شده باشد، دیگر چیپ قرمزِ بی‌پایان نمی‌ماند —
  اپ نشست را می‌بندد و می‌گوید «دوباره وارد حساب شو» (ورود مجدد = برگشت کامل داده‌ها).
- **پیش‌پرواز سبک‌تر:** مسابقهٔ دو مسیر در بوت حالا با GET /version.json (بدون بدنه و
  بدون وابستگی به CORS) انجام می‌شود — سبک‌تر و سریع‌تر؛ و «تست اتصال» پروفایل با
  POST /api/ping و بررسی بدنهٔ {ok:true} — تست واقعی و قابل‌اعتماد.
- **حجم دادهٔ همگام‌سازی** در پروفایل نمایش داده می‌شود (کیلوبایت).
- APP_VERSION → `۲.۱۱.۱۵`، نسخهٔ کش سرویس‌ورکر → `gh7`.
- **ورکر عوض نشده** — این نسخه فقط سمت صفحه (GitHub Pages) است؛ نیازی به آپدیت Cloudflare نیست.

## به‌روزرسانی این نسخه
فایل‌های جدید (index.html / sw.js / version.json / ...) را با «Add file → Upload files»
روی همین ریپو جایگزین کنید؛ GitHub Pages خودکار منتشر می‌کند (۱-۲ دقیقه).
فایل‌های مخفی موجود (مثل .nojekyll و .well-known) را پاک نکنید.

## تست بعد از انتشار
1. اپ نصب‌شده را کامل ببندید و دوباره باز کنید (دو بار، تا سرویس‌ورکر جدید بنشیند).
2. در پروفایل، نسخه باید «۲.۱۱.۱۷» باشد.
3. «تست اتصال سرور» را بزنید — هر دو مسیر باید ✓ با زمان پاسخ باشند.
4. اگر چیپ قرمز برگشت، از پروفایل «آخرین خطای همگام‌سازی» را اسکرین‌شات بگیرید — علت دقیق را می‌گوید.
